## ج) حکمِ صریح برای go-live کیان‌فولاد

**خیر — با hidden_tabs فعلی، زنجیرهٔ میلگرد «بسته» نیست.** زنجیره در سه نقطه می‌شکند:

1. **شمش ورودی ثبت نمی‌شود** (رسید خرید پنهان = حلقهٔ ۱) ⇒ **آزمون ورودی QC ناممکن** (پیش‌نیاز GRN در server.js:7569) ⇒ **MTC هرگز صادر نمی‌شود** (7820-7823).

3. **حواله/فاکتور فروش و دفتر مالی قابل مشاهده نیستند** (حلقه‌های ۷/۸) و پرچم کمبود شمش APS همیشه به «پایهٔ مهندسی» سقوط می‌کند (3455).

آنچه **سالم کار می‌کند**: ثبت تولید (با هیت)، ضایعات، توقفات، PM، برنامه‌ریزی در حالت شروع سرد، QC-PRO مستر گرید/مشخصات/مستر پارامترهای 43، و NCR (scope هیت/رسید — فقط بندیل‌scope بی‌اثر است).

### حداقلِ تغییرِ امن برای go-live (پیشنهاد، به ترتیب هزینه)
1. **صفرِ کد:** بازگرداندن `purchase` و `warehouse` به visible در tenant.json (حلقهٔ ۱ + ۶ باز؛ آزمون QC و پرچم کمبود با تنظیم tenant به زنجیره وصل می‌شوند) — اگر پنهان‌سازی تجاری است، حداقل نقشِ qc/انباردار این دو تب را ببیند.

4. تب‌های finance/sales/genealogy/balance: تصمیم تجاری؛ تا باز نشدن، اسناد خودکار مالی انباشته می‌شوند و MTC بدون حواله فقط با `order_id` (server.js:7790) کار می‌کند.

### گاردهای پیاده‌سازی
- **سوییچ‌ها فقط مدیرعامل (CEO):** PUT /api/tenant/config اگر `custom_settings` شامل هر یک از سه سوییچ باشد و درخواست‌دهنده vendor/owner نباشد ⇒ 403 OWNER_ONLY + audit `tenant.switch_owner_denied` — همان اولویتِ مطلق hidden_tabs؛ admin مشتری نمی‌تواند خودش قابلیتِ پنهان‌شده را برگرداند. راه فعال‌سازی: ویرایش `tenant.json` → `custom_settings` (خواندن با کش mtime — بدون ری‌استارت) یا PUT با حساب مدیرعامل.
- **افشای محدود:** GET /api/tenant/config فقط `feature_flags` (سه boolean) را می‌فرستد — کل custom_settings افشا نمی‌شود.
- **بدون سوییچ، رفتار سابق بایت‌به‌بایت:** هر سه مسیر با `cs.x !== true` بلافاصله مسیر قدیمی می‌روند.
